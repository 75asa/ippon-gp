## webrtc-internals の読み方

MAIN PC の Chrome で `chrome://webrtc-internals` を開くと、CAM からの接続が 1 つ表示される。見る場所は 3 つ。

| 項目 | 場所 | 正常 | 異常時の意味 |
|---|---|---|---|
| 解像度 | `inbound-rtp (kind=video)` の `frameWidth` / `frameHeight` | 1920×1080（最低 1280×720） | 640×480 → CAM 側の解像度指定が消えている（#59。カメラ切替後に起きる） |
| ビットレート | 同じ `inbound-rtp` の `bytesReceived` の増え方（グラフ） | 数 Mbps で安定 | 1 Mbps 未満で上下 → 帯域不足 |
| 制限理由 | CAM 側 `outbound-rtp` の `qualityLimitationReason`（MAIN からは接続先の統計として見える。CAM の status 欄に表示する機能は #63） | `none` | 下表 |
| 経路 | `candidate-pair`（`state=succeeded`）の `local` / `remote` の candidate type | `host` / `host` | `srflx` → NAT 越え（別ネットワーク）、`relay` → TURN 経由（現状は無いので出ないはず） |

### `qualityLimitationReason` の値

| 値 | 意味 | 対処 |
|---|---|---|
| `none` | 制限なし。指定どおりの解像度で送れている | それでも粗いなら解像度指定の問題（#59）。`frameWidth` を確認 |
| `bandwidth` | ネットワーク帯域が足りず、解像度 / フレームレートを落としている | CAM スマホと MAIN PC を **同一ルーター（5GHz）またはテザリング** に。会場 Wi‑Fi から離脱。CAM を停止→再開で帯域推定をリセット |
| `cpu` | CAM スマホの処理が追いつかない（発熱・他アプリ） | スマホを冷ます / 再起動、他アプリ終了、給電。改善しなければ解像度を 720p に落として安定させる |
| `other` | 上記以外（まれ） | CAM を停止→再開。改善しなければ HDMI キャプチャへ |

## 前提の確認事項（最優先）

1. **ライセンス**: 本家には LICENSE が無い。GitHub 規約上「閲覧・フォーク」は許されるが、改変物の再配布や商用利用（SaaS）は明示的な許諾が必要。
   → 本家作者に **MIT（または Apache-2.0）での公開** を依頼する Issue / 連絡を行う。合意が取れるまで LICENSE ファイルはフォークにも置かない。
2. **素材の権利**: 効果音・画像・OP 動画は本家作者または会社の制作物。フォークの Storage にコピーする前に権利を確認する。SaaS ではユーザー持ち込み素材 + 自前制作のデフォルト素材に置き換える。
3. **商標**: 「IPPON グランプリ」はテレビ番組名。社内利用はパロディとして許容範囲でも、SaaS の名称・宣伝には使わない。

## 進め方

- 本家 `main` をフォークの `main` に定期的に取り込む（`git fetch upstream && git merge upstream/main`）。
- 本家向け PR は **フォークの `main` から切った専用ブランチ** で、変更を 1 関心事に絞る。フォーク固有の差分を含めない。
- 本家作者のレビュー負荷を下げるため、PR には「動作確認手順」と「後方互換性（既存 HTML がそのまま動くか）」を必ず書く。
- 本家がマージしない判断をした変更は、フォーク側で維持する（`docs/UPSTREAM.md` に差分一覧を残す）。
